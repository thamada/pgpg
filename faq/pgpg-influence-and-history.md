# PGPG の影響と計算機アーキテクチャ史における位置づけ

> **概要**: 本記事は、PGPG（Pipeline Generator for Programmable GRAPE）がその後に与えた影響、GPU・AIチップとの思想的共通点、GRAPE研究がGPUに負けた理由、および日本が専用計算機では世界最強だったにもかかわらずAIチップ競争で遅れた背景を、計算機アーキテクチャの歴史として整理する。
>
> **関連**: [paper/README.md](../paper/README.md)（時代背景・先行研究・GRAPE系譜）、[doc/design.md](../doc/design.md)（PGPG設計仕様）

---

## 1. PGPG がその後に与えた影響

PGPG は 2000 年代前半の比較的ニッチな研究プロジェクトであったが、いくつかの重要な技術的流れに影響を与えた。特に以下の 3 つの分野で影響が見られる。

### 1.1 FPGA アクセラレータの「自動生成」という発想

PGPG の最も重要な影響は、**「数式レベルの記述から FPGA パイプラインを自動生成する」**という考え方を示したことである。

PGPG は次の一括生成を実現した：

| 入力 | 出力 |
|------|------|
| **PGDL**（高レベル言語） | **VHDL** 回路 |
| | **通信ライブラリ** |
| | **ホスト制御コード** |

つまり、**数値計算 → ハードウェア回路**をコンパイラ的に変換する仕組みである。

当時の FPGA 開発は、VHDL/Verilog の手書き、通信コードの手書き、データフォーマットの手書きで、研究用途でも **1 人年以上**かかることがあったと報告されている（[Hamada et al. 2005](https://arxiv.org/abs/astro-ph/0703182)、[PROGRAPE-1](https://arxiv.org/abs/astro-ph/9906419)）。

PGPG はこれを **高レベル DSL → FPGA 回路** に変えた。この思想は後に次の技術に強く受け継がれる：

- **FPGA High-Level Synthesis (HLS)**
- **ハードウェア DSL**（Chisel など）
- **AI アクセラレータコンパイラ**（Halide、TVM など）

したがって、**PGPG = HLS の先駆的研究** と言われることがある。

### 1.2 PROGRAPE / GRAPE 研究のソフトウェア化

PGPG は、天体計算専用計算機 **GRAPE シリーズ**の発展の中で生まれた。

| 段階 | 特徴 |
|------|------|
| **GRAPE** | N 体問題専用 LSI、超高速、用途が固定 |
| **PROGRAPE** | FPGA 上にパイプライン、計算内容を変更可能 |
| **PGPG** | パイプライン設計の自動生成により設計生産性を飛躍的に向上 |

進化の流れ：

```
GRAPE (ASIC)
    ↓
PROGRAPE (FPGA)
    ↓
PGPG (自動生成)
```

この流れは後に **GRAPE-DR**、**GRAPE-9** などの研究に影響を与えている。

### 1.3 後継ツール（PGR / PGPG2）

PGPG の後には改良版が作られている。

| ツール | 概要 |
|--------|------|
| **PGR**（Pipeline Generator for Reconfigurable computing） | 数式を入力すると FPGA パイプラインを生成。PGPG のアイデアを発展させたもの。[Nakasato et al. (2006)](https://arxiv.org/abs/astro-ph/0604295) で PROGRAPE-3 上に SPH パイプラインを初実装 |
| **PGPG2** | GRAPE-9 世代向け。新しい DSL（PG2）で VHDL + C ライブラリを生成。PGPG の後継として研究されている |

### 1.4 FPGA HLS への思想的影響

PGPG は直接の主流ツールではなかったが、現在の FPGA 開発の方向性を先取りしていた。

| 技術 | 概要 |
|------|------|
| Xilinx Vitis HLS | C/C++ から回路生成 |
| Intel HLS | C ベース合成 |
| Chisel | ハードウェア DSL |
| Halide / TVM | アクセラレータ生成 |

これらはすべて **アルゴリズム → パイプライン回路** を自動化する思想である。PGPG は 2000 年代初頭に次の変換を実装していた：

```
数式 → パイプライン → FPGA
```

この点で、**アクセラレータコンパイラの初期例** とみなされる。

### 1.5 GPU 時代との関係

PGPG が作られた頃は、まだ **GPGPU**（GPU 汎用計算）が普及していなかった。2006〜2010 年頃に CUDA と GPU 並列計算が急速に発展し、結果として：

```
FPGA アクセラレータ研究
    ↓
GPU の圧倒的普及
```

となり、PGPG 系の研究は主流にはならなかったという側面もある。

ただし現在は、**AI アクセラレータ**、**FPGA クラウド** などで、再び同じ発想が重要になっている。

## 2. PGPG と GPU の思想的共通点

PGPG・GPU・TPU は一見異なるが、根本思想はかなり共通している。

### 2.1 共通点：大量の同じ計算を並列に処理する

PGPG が対象にしていた計算は主に **N 体問題**（粒子同士の相互作用）である。

```c
for (i = 0; i < n; i++) {
  for (j = 0; j < n; j++) {
    force[i] += f(particle[i], particle[j]);
  }
}
```

これは **同じ計算を何百万回も繰り返す** タイプの処理である。この構造は、画像処理、物理シミュレーション、深層学習にも共通する。つまり **同じ演算を大量データに適用** する **データ並列計算** である。

### 2.2 PGPG のアプローチ

| 段階 | 内容 |
|------|------|
| 入力 | 数式（PGDL） |
| 変換 | パイプライン生成 |
| 出力 | FPGA 回路 |

特徴：演算器を深いパイプラインにし、同じ計算を流し続けて高スループットを実現する。

### 2.3 GPU のアプローチ

| 段階 | 内容 |
|------|------|
| 入力 | 同じ命令（カーネル） |
| 実行 | 大量スレッド |
| 方式 | SIMD 実行 |

NVIDIA の CUDA は `kernel()` を数千スレッドで GPU に流す。

### 2.4 比較まとめ

| 項目 | PGPG | GPU |
|------|------|-----|
| 方式 | 専用パイプライン生成 | 汎用 SIMD |
| ハードウェア | FPGA | GPU |
| 入力 | 数式 → 回路 | C → カーネル |

しかし本質は同じである：**同じ演算を大量に並列化する**。

## 3. なぜ日本の GRAPE 研究は GPU に負けたのか

GRAPE は東京大学を中心に開発された天体計算専用スーパーコンピュータである。GRAPE-4、GRAPE-6 は 1990 年代に世界最速クラスであった。しかし GPU に負けた理由は主に 4 つある。

### 3.1 市場規模

| 対象 | 市場 | 規模 |
|------|------|------|
| **GPU** | ゲーム市場 | 数億台 |
| **GRAPE** | 研究機関 | 数十台 |

GPU 企業は毎年数十億ドル規模の R&D を投入できる。GRAPE は研究装置であり、その規模には届かない。

### 3.2 汎用性

| 対象 | 用途 |
|------|------|
| **GRAPE** | 重力計算ほぼ専用 |
| **GPU** | 画像、AI、科学計算、物理など |

2006 年頃、NVIDIA が CUDA を公開し、GPU が **汎用並列計算機** になったことが決定打であった。

### 3.3 プログラミングの容易さ

| 対象 | 開発環境 |
|------|----------|
| **GRAPE / PGPG** | FPGA 設計、専用 API、研究者向け |
| **GPU** | C 言語 + CUDA |

この差は大きかった。

### 3.4 半導体の進化速度

| 対象 | 更新頻度 |
|------|----------|
| **GPU** | 毎年新世代（GeForce 8800 GTX → Tesla V100 → H100） |
| **GRAPE** | 数年に 1 回 |

2010 年頃には **GPU ≧ GRAPE** となり、GPU が科学計算の主流になった。

## 4. PGPG と現代 AI チップ（TPU）の共通点

現在の AI アクセラレータの代表である **Google TPU** と PGPG には、構造的な類似性がある。

### 4.1 TPU の基本思想

TPU は **行列演算専用プロセッサ** である。ニューラルネットの計算は \( Y = W \times X \) という **巨大行列積** になる。

TPU 内部には **systolic array**（シストリックアレイ）という構造がある。データを格子状の演算器に流し、隣接ユニット間でパイプライン的に処理する。

### 4.2 PGPG との共通点

| 項目 | PGPG | TPU |
|------|------|-----|
| 回路 | 専用計算回路 | 専用 AI 回路 |
| 構造 | パイプライン | systolic array |
| 中心演算 | 数式（N 体） | 行列演算 |
| 目標 | 高スループット | 高スループット |

どちらも **アルゴリズムに特化したハードウェア** である。

### 4.3 変換の類似

| 段階 | PGPG | TPU |
|------|------|-----|
| 入力 | 数式（PGDL） | TensorFlow 等 |
| 変換 | パイプライン生成 | コンパイラ |
| 出力 | FPGA | アクセラレータ |

構造が非常に似ている。

## 5. 歴史の流れ

全体の流れをまとめると：

```
1990s  GRAPE（専用 ASIC）
    ↓
2000s  PGPG / PROGRAPE（FPGA アクセラレータ）
    ↓
2010s  GPU（CUDA）
    ↓
2020s  AI 専用チップ（TPU / NPU）
```

PGPG は **AI アクセラレータ研究のかなり早い先祖** とも言える。

## 6. なぜ日本は専用計算機では世界最強だったのに AI チップでは遅れたのか

日本は 1990 年代〜2000 年代初めには専用計算機で世界最強クラスであった。しかし現在の AI チップ競争では米国・中国企業が主導している。この差は、技術力ではなく **産業構造・ソフトウェア・市場** の違いで説明されることが多い。

### 6.1 日本は「専用計算機」では本当に世界最強だった

| システム | 実績 |
|----------|------|
| **GRAPE-6** | 約 64 TFLOPS、N 体問題で世界最速（2002 年頃） |
| **Earth Simulator** | 2002 年 TOP500 世界 1 位 |
| **京コンピュータ** | 2011 年 TOP500 世界 1 位 |
| **富岳** | 2020 年 TOP500 世界 1 位 |

日本は **科学計算専用スーパーコンピュータ** では世界の中心であった。

### 6.2 AI チップの時代になると状況が変わる

現在の AI アクセラレータの代表例：Google TPU、NVIDIA H100、AMD MI300。開発主体は NVIDIA、Google、AMD など **米国の巨大 IT 企業** である。

### 6.3 最大の理由：ソフトウェアエコシステム

AI チップで最も重要なのはハードウェアではなく **ソフトウェア** である。

AI 研究者が使う環境は **CUDA**、**PyTorch**、**TensorFlow** であり、これらはすべて米国企業・米国大学が中心になって作った。結果として：

```
AI 研究者 → CUDA / PyTorch → NVIDIA GPU
```

という **巨大なロックイン** ができた。

日本は **ハードウェア研究は強いが、ソフトウェア基盤は弱い** という構造であった。

### 6.4 研究 vs 産業

| 対象 | 主体 |
|------|------|
| **GRAPE / PGPG** | 東京大学、理化学研究所などの大学研究プロジェクト |
| **GPU** | 巨大産業（NVIDIA の R&D 費は年 100 億ドル以上） |

大学研究と産業では桁が違う。

### 6.5 半導体産業の衰退

| 時期 | 日本の半導体シェア |
|------|-------------------|
| 1990 年頃 | 世界の約 50% |
| 現在 | TSMC、Samsung、Intel が中心。先端ロジックを作れる企業が日本にはほぼない |

AI チップは **最先端プロセス** が必要である。

### 6.6 AI 革命の中心が「IT 企業」だった

AI ブームの中心は Google、Meta、Microsoft、OpenAI など **巨大クラウド企業** である。AI チップは **クラウド用アクセラレータ** として発展した。日本にはこの規模の企業がなかった。

### 6.7 日本の計算機研究の方向

日本は長い間 **HPC（スーパーコンピュータ）** 中心であった。富岳は 2020 年に TOP500 で世界 1 位であった。しかし AI の主戦場は **クラウド + GPU** であった。

### 6.8 まとめ：遅れた 5 つの理由

1. **ソフトウェアエコシステム** — CUDA / PyTorch を作れなかった  
2. **産業規模** — 大学研究 vs 巨大 IT 企業  
3. **半導体製造** — 先端プロセスの喪失  
4. **市場** — 科学計算 vs AI クラウド  
5. **研究文化** — HPC 重視  

一言でまとめると：**日本は「科学計算機」は強かったが「AI 産業」を作れなかった。**

## 7. 日本の AI チップの現状：Preferred Networks

2020 年代において、日本は **Preferred Networks（PFN）** の MN-Core シリーズが一定の存在感を示している。

| 項目 | 内容 |
|------|------|
| **MN-Core** | 2020〜2021 年に Green500 で世界 1 位を 3 度獲得 |
| **MN-Core 2** | 2023 年稼働開始、2024 年 9 月から販売 |
| **MN-Core L1000** | 生成 AI 推論専用プロセッサ、2026 年提供目標。三次元積層 DRAM 技術、既存 GPU 比最大 10 倍の高速処理を目指す |

一方で、NVIDIA、AMD、Google、Amazon などに比べて市場規模・エコシステム・顧客基盤の面で存在感は限定的である。詳細は [paper/README.md 第 5 節](../paper/README.md) を参照。

## 8. まとめ

PGPG の影響を一言でまとめると：

1. **FPGA アクセラレータ生成の先駆け** — 数式から回路を自動生成する思想を示した  
2. **GRAPE → PROGRAPE 研究をソフトウェア化** — 設計生産性の壁を解消した  
3. **HLS / ハードウェア DSL の思想を先取り** — 現在の FPGA 開発の方向性を 2000 年代初頭に実装した  

つまり、**「アルゴリズムを記述すると専用ハードウェアが生成される」** という現在のアクセラレータ研究の基本概念を、かなり早い時期に実装した研究である。

PGPG と GPU、TPU は、いずれも **同じ演算を大量並列化する** という共通思想を持ち、計算機アーキテクチャ史において連続した発展の一環として位置づけられる。
